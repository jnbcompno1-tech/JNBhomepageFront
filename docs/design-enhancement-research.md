# JNB 홈페이지 디자인 고도화: 기술·템플릿 조사

조사일: 2026-10-12 · 대상: https://jnb-company.vercel.app/

이 문서는 후보 조사와 적용 제안이다. 패키지 설치, 템플릿 구매, 홈페이지 구현·배포는 포함하지 않는다. 추천 순위와 난이도는 현재 JNB 코드와 고객 특성에 대한 판단이며, 도입 후 효과나 성능을 실측한 결과는 아니다.

## 1. 추천 방향

**밝은 산업·기술 기업 스타일에 실제 제품 사진, 크기가 다른 사례 배치, 짧고 절제된 움직임을 결합하는 방향을 추천한다.**

우선 볼 자료는 세 가지다.

1. [Studio 데모](https://studio.tailwindui.com/): 큰 제목, 여백, 프로젝트를 보여주는 방식의 참고 자료. 전체 사이트 구성에 가장 가까운 후보다.
2. [React Bits — Spotlight Card](https://reactbits.dev/components/spotlight-card): 카드 위에 마우스를 올리면 부드러운 빛이 따라오는 효과. 한두 곳에 적용할 장식 후보다.
3. [Motion for React](https://motion.dev/docs/react): 스크롤 등장·카드 전환 등 여러 움직임이 필요할 때 사용할 구현 도구다.

추천 조합은 **기존 Next.js + CSS Modules 유지 → 사진·타이포그래피·배치 개선 → 필요한 모션만 추가**다. 카드 hover 정도는 CSS로 충분하다. 여러 등장·상태 전환을 함께 관리할 필요가 생길 때 Motion 하나를 추가한다. 템플릿 전체 교체와 여러 효과 라이브러리의 동시 도입은 우선순위가 낮다.

## 2. 현재 홈페이지에서 확인한 점

운영 홈페이지를 Edge 기반 브라우저로 열어 1440px·390px 화면을 확인했다. 아래 평가는 홈 화면에 대한 관찰이며 전체 페이지의 디자인·접근성 감사는 아니다.

| 현재 모습 | 개선 기회 |
| --- | --- |
| 흰색·옅은 회색·파란색 중심의 일관된 색상 | 기본 팔레트는 유지하고 사진·타이포그래피로 브랜드 인상을 강화 |
| 첫 화면 오른쪽에 CSS로 만든 추상적인 JNB 제품 그래픽 | 실제 취급 부품이나 수행 제품을 보여주면 업종이 더 빨리 전달됨 |
| 포트폴리오와 사업영역이 비슷한 3열 카드로 이어짐 | 대표 사례 하나를 크게 보여주고 나머지를 보조 배치하여 중요도 구분 |
| 제품 사진·설명 이미지·공장 이미지의 표현 방식이 다름 | 배경색, 제품 크기, 이미지 여백과 비율을 정리하면 통일감 개선 |
| 여백은 넉넉하지만 반복되는 구획이 많음 | 여백을 무조건 늘리기보다 이미지 중심 영역과 정보 중심 영역에 차이를 줌 |
| 모바일은 카드가 한 열로 길게 이어짐 | 요약 정보와 대표 사례를 먼저 보여주고 전체 목록으로 이동하는 흐름 강화 |
| 메시지가 아이디어·디자인부터 생산까지 넓게 설명됨 | 사용자가 밝힌 주 고객인 양산 부품 구매 담당자에게 필요한 정보를 더 앞에 둘 여지 |

마지막 항목은 콘텐츠 방향 제안이다. 중국 현지 소통, 공급 안정성, 원가 절감 실적 등 구체적인 역량·성과 문구는 확인된 범위 안에서 작성한다. 장식용 수치나 고객 로고를 추가하지 않는다.

### 현재 기술 구조

- `package.json`: Next.js 16.4.0, React 19.3.0, TypeScript. 현재 Tailwind·Motion·GSAP 패키지는 없다.
- `src/app/page.tsx`: 첫 화면, 대표 포트폴리오, 사업영역, 진행 과정, 문의 CTA.
- `src/components/Site.tsx`: 여러 페이지에서 쓰는 카드·진행 과정·CTA·푸터.
- `src/components/Site.module.css`, `src/app/globals.css`: CSS Modules와 전역 스타일.
- `src/components/Header.tsx`: 모바일 메뉴를 처리하는 클라이언트 컴포넌트.
- 기존 `next/image`와 제품 사진을 재사용할 수 있다. 현재 원본 사진의 사용 맥락은 [자산 목록](asset-register.md)을 기준으로 한다.

[가독성 개선 계획](readability-plan.md)은 선행 작업이다. 다른 세션의 구현과 운영 배포 시점이 다를 수 있으므로 후속 구현은 최신 체크아웃을 기준으로 한다. 기존 graphify 자료는 현재 JNB 파일 구조와 달라 기술 판단은 실제 소스 파일로 확인했다.

## 3. 디자인 방향 비교

| 방향 | 화면 인상 | JNB 적용 판단 | 필요한 자료 |
| --- | --- | --- | --- |
| **A. 밝은 산업·기술 기업형 — 추천** | 흰 배경, 짙은 제목, 파란 강조색, 크게 보이는 실제 제품 | 부품·소싱·양산 정보를 전달하면서 현재 브랜드를 발전시키기 좋음 | 대표 제품 사진, 핵심 사업·수행 범위 |
| B. 프로젝트 중심 스튜디오형 | 큰 제목, 비대칭 구성, 사례 이미지 중심 | 실적을 보여주기 좋지만 디자인 에이전시로만 보이지 않게 조정 필요 | 사례별 사진, 수행 역할, 공개 가능한 설명 |
| C. 어두운 기술 쇼케이스형 | 광원·그라데이션·3D·스크롤 연출 | 기술적인 인상은 강하지만 부품 비교와 긴 업무 설명에는 조절 필요 | 수준이 일정한 렌더링·영상·3D 자산 |

A를 기본으로 B의 사례 구성을 일부 가져오는 조합을 우선 제안한다. C의 빛 효과는 첫 화면이나 CTA 한 곳에서만 시험한다.

산업 분야의 정보 구성 참고로는 [Protolabs](https://www.protolabs.com/)의 서비스·제품 이미지·견적 진입 구조와 [Fictiv](https://www.fictiv.com/)의 제조·소싱 안내를 볼 수 있다. 이는 정보 전달 방식의 참고이며 JNB가 같은 설비·인증·생산 규모를 보유한다는 뜻은 아니다.

## 4. 기술·컴포넌트 후보

난이도는 현재 CSS Modules 프로젝트에 도입할 때의 상대적인 범위다. 무료 여부와 실제 개발·자산 제작 비용은 별개다.

| 후보 | 사용자에게 보이는 변화 | JNB 적용 위치 | 도입 부담 | 판단 |
| --- | --- | --- | --- | --- |
| CSS Grid·transition + Intersection Observer | 다양한 카드 크기, 자연스러운 hover, 화면 진입 시 짧은 등장 | 사례·사업영역·진행 과정 | 낮음. 별도 UI 패키지 불필요 | **기본 선택** |
| Motion for React | 순차 등장, 상태 전환, 레이아웃 변화 | 대표 사례·진행 과정 | 낮음~중간. 애니메이션 영역의 클라이언트 코드 필요 | **효과가 여러 곳에 필요할 때** |
| React Bits | Spotlight Card·Fade Content 등 선택형 효과 | 첫 화면·강조 카드 한두 곳 | 중간. 컴포넌트별 의존성 확인 | **효과 후보 중 우선 검토** |
| Magic UI | Bento Grid·Magic Card 등 카드와 강조 효과 | 요약 사업영역·대표 사례 | 중간. Tailwind 기반 예제의 스타일 이식 또는 환경 추가 | 부분 참고 |
| Aceternity UI | Spotlight·Bento 등 시각적 강조 | 첫 화면 배경·CTA | 중간. 예제별 Tailwind·Motion 등 확인 | 효과 한 곳에 한정 |
| shadcn/ui | 일관된 버튼·탭·Dialog 등 UI 기반 | 추후 필터·자료 보기 등 상호작용 | 중간. 설정·스타일 체계 도입 필요 | 실제 기능 필요 시 검토 |
| GSAP + ScrollTrigger | 스크롤에 맞춘 여러 장면의 순차 연출 | 제조·공급 과정 소개 | 중간~높음. 타임라인·스크롤·정리 로직 관리 | 현재 범위에서는 보류 |
| Spline | 회전하거나 반응하는 3D 제품 | 첫 화면의 대표 제품 | 높음. 씬 제작·런타임·성능 검증 필요 | 3D가 제품 설명에 필요할 때 |

### 4.1 CSS와 브라우저 기본 기능

첫 적용은 카드 테두리·그림자·이미지 확대 같은 작은 변화와 CSS Grid 배치로 충분하다. 화면에 들어오는 시점 감지는 [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)로 구현할 수 있다. Bento는 크기가 다른 타일을 조합하는 배치 방식이므로 전용 라이브러리가 필수는 아니다.

제안값은 hover 150~220ms, 등장 300~450ms, 이동 거리 8~16px 정도다. 이는 JNB 시안의 시작값이며 표준 요구사항은 아니다. 긴 설명 전체에 지연을 주지 않고, 제목·연락처·문의 버튼은 즉시 읽을 수 있게 한다.

[View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)는 화면 변경을 이어주는 후보지만 현재 App Router와의 결합·브라우저별 동작을 검증하지 않았다. 초기 개선의 필수 조건으로 삼지 않는다.

### 4.2 Motion for React

[공식 문서](https://motion.dev/docs/react)는 `whileInView`, 레이아웃·제스처 애니메이션 등을 제공한다. 핵심 라이브러리와 유료 Motion+ 자료는 구분해야 한다. 핵심 소스는 [MIT 라이선스](https://github.com/motiondivision/motion/blob/main/LICENSE.md)다.

JNB에서는 카드의 짧은 순차 등장과 진행 단계 강조에 적합하다. [Next.js 설치 안내](https://motion.dev/docs/react-installation)에 맞춰 움직이는 영역만 분리하고 페이지 전체를 불필요하게 클라이언트 컴포넌트로 바꾸지 않는다. [번들 크기 안내](https://motion.dev/docs/react-reduce-bundle-size)를 참고하되 실제 증가량은 빌드로 확인한다.

CSS만으로 충분한 상태에서는 설치하지 않는다. 도입한다면 같은 일을 하는 GSAP나 다른 등장 효과 라이브러리를 함께 넣지 않는 편을 권한다.

### 4.3 React Bits

- [Spotlight Card](https://reactbits.dev/components/spotlight-card): 포인터를 따라 은은하게 밝아지는 카드. 대표 사례나 CTA 외곽에 제한적으로 적용.
- [Fade Content](https://reactbits.dev/animations/fade-content): 내용의 등장·퇴장 효과. 단순 등장만 필요하면 직접 CSS로 구현하는 대안과 비교.
- [Aurora](https://reactbits.dev/backgrounds/aurora): 흐르는 빛 배경. 첫 화면의 낮은 우선순위 실험 후보이며 본문 뒤에는 사용하지 않음.

공식 페이지에서 TypeScript와 일반 CSS 또는 Tailwind 방식을 제공하므로 현재 프로젝트에는 일반 CSS 방식을 먼저 검토할 수 있다. 일반 CSS라도 컴포넌트별 JavaScript 의존성이 없다는 뜻은 아니다.

조사일 기준 [라이선스](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md)는 **MIT + Commons Clause**다. 본문에는 상업적 웹사이트·제품에서의 사용과 컴포넌트 자체의 판매·재배포 제한이 명시돼 있다. 순수 MIT로 기록하지 않으며, Pro 상품은 별도 조건을 확인한다.

### 4.4 Magic UI·Aceternity UI·shadcn/ui

[Magic UI Bento Grid](https://magicui.design/docs/components/bento-grid)는 사례별 비중을 다르게 보여주는 참고 자료다. [Magic Card](https://magicui.design/docs/components/magic-card)는 카드 광원 효과 후보다. 공개 저장소는 [MIT](https://github.com/magicuidesign/magicui/blob/main/LICENSE.md)이며 유료 상품까지 같은 조건이라고 가정하지 않는다. 현재 JNB에는 Tailwind가 없으므로 코드 복사가 즉시 적용을 의미하지 않는다.

[Aceternity Spotlight](https://ui.aceternity.com/components/spotlight)는 배경 빛 연출 후보이며 [컴포넌트·블록 목록](https://ui.aceternity.com/explore)에서 다른 배치를 비교할 수 있다. [라이선스 안내](https://ui.aceternity.com/licence)는 Pro 항목 조건을 설명한다. 선택한 무료·유료 항목의 정확한 적용 조건과 의존성을 확인한 뒤 도입한다.

[shadcn/ui Blocks](https://ui.shadcn.com/blocks)는 공개 컴포넌트·블록 모음이다. 확인한 목록에는 대시보드·로그인·사이드바 등이 있어 회사 소개 사이트의 완성형 템플릿과는 용도가 다르다. [Next.js 설치 안내](https://ui.shadcn.com/docs/installation/next)를 참고하되 버튼 디자인만 바꾸려고 전체 체계를 도입할 필요는 없다.

### 4.5 GSAP·Spline

[GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)는 복잡한 스크롤 연출을 위한 후보다. [공식 가격 페이지](https://gsap.com/pricing/)는 전체 GSAP 라이브러리 무료 제공을 안내한다. 무료라는 사실만으로 MIT 라이선스와 같다고 해석하지 않는다. JNB의 현재 정보량에는 제작·유지 비용이 더 큰 선택으로 판단한다.

[Spline React 연동](https://github.com/splinetool/react-spline)은 씬과 런타임을 웹사이트에 넣는 방식이다. 연동 패키지의 라이선스와 [Spline 서비스 요금](https://spline.design/pricing)은 별개다. 실제 제품을 설명하는 3D 자산이 있을 때 검토하고, 단순 장식은 정적인 제품 사진이나 CSS/SVG 그래픽으로 먼저 해결한다.

## 5. 실제 템플릿 후보

### 5.1 Tailwind Plus — Studio: 구성 참고 1순위

- [직접 보는 데모](https://studio.tailwindui.com/) · [공식 템플릿 페이지](https://tailwindcss.com/plus/templates/studio/preview)
- 공식 검색 결과는 Next.js·Tailwind CSS·React·MDX·Framer Motion 기반 에이전시 템플릿으로 소개한다. 데모 첫 화면은 직접 브라우저로 확인했다.
- 큰 제목, 넉넉한 여백, 작업 사례·업무 과정·회사 소개·문의로 이어지는 구성을 JNB에 참고하기 좋다.
- JNB에서는 제품 사진과 공급·양산 사례를 주인공으로 바꾸고, 고객에게 익숙한 상단 메뉴를 유지하는 편을 제안한다.
- 유료 구매 후보지만 조사 도구에서 판매·라이선스 페이지가 로그인 화면으로 연결되어 **현재 구매 금액·상세 이용 조건은 확인하지 못했다**. 구매 전 확인이 필요하다.
- 코드 전체를 옮기면 Tailwind와 관련 구조를 도입해야 한다. 현 단계에서는 레이아웃 원칙을 참고해 기존 코드로 구현하는 쪽이 부담이 작다. 유료 코드·이미지를 무단 복사하지 않는다.

### 5.2 Framer — Industrial Factory: 산업 분야 정보 구성 참고

- [마켓플레이스](https://www.framer.com/marketplace/templates/industrial-factory/) · [데모](https://fancy-mindset-208002.framer.app/)
- 판매자 설명은 제조 역량, 설비, 품질, 프로젝트와 견적 문의를 연결하는 산업용 템플릿이다. 제품·공급 사례에서 문의로 이어지는 흐름을 참고할 만하다.
- 조사일 표시는 **$39 / Single-Use**, 게시·수정일은 2026-10-10이었다. 요금·범위는 구매 시 다시 확인한다. Framer 운영 비용은 템플릿 가격과 별도로 검토한다.
- Framer용 템플릿이므로 현재 Next.js 저장소에 바로 설치하는 제품은 아니다. 직접 사용하려면 운영 방식 변경과 재구성이 필요하다.
- JNB에 없는 설비·인증·납기 수치를 채워 넣지 않는다. 대형 공장 사진이 자사 보유 시설로 오인되지 않도록 맥락을 명확히 한다.
- 데모는 이번 자동 브라우저의 로딩 완료 대기에서 시간 초과가 발생했다. 여기의 기능 설명은 마켓플레이스 기준이며, 동작·접근성·성능은 검증하지 않았다.

### 5.3 Cruip — Open: 무료 코드 참고 후보

- [공식 저장소](https://github.com/cruip/open-react-template) · [저장소에서 연결한 데모](https://open.cruip.com/)
- Next.js·Tailwind 기반 랜딩 페이지다. 기능 설명과 CTA 구성에 참고할 수 있지만 SaaS 성격이 강해 JNB의 제품·공급 사례에 맞게 조정해야 한다.
- README는 무료 사용과 함께 GPL 표기 및 템플릿 재배포 관련 문구를 제공한다. **MIT로 분류하지 않는다.** 코드 채택 전 적용 버전의 조건을 확인한다.
- 연결된 데모의 페이지 제목은 Open PRO였다. 데모에서 보이는 전체 섹션이 무료 저장소에 포함된다고 가정하지 않는다.
- Tailwind 이식 작업과 표현 변경이 필요하므로 무료 다운로드가 가장 짧은 구현을 보장하지는 않는다.

## 6. JNB에 적용할 구체적인 화면 제안

| 영역 | 제안 | 효과·구현 후보 | 우선순위 |
| --- | --- | --- | --- |
| 첫 화면 | 주요 업무를 읽을 수 있는 제목 + 대표 제품 사진 1장 또는 소수의 제품 구성 | CSS Grid, 절제된 배경 그라데이션. 제목·CTA 즉시 노출 | 높음 |
| 대표 포트폴리오 | 대표 사례를 크게, 나머지를 작게 배치. 제품·수행 역할·관련 품목을 쉽게 구분 | CSS Grid 기반 비대칭 카드. 작은 화면에서는 의미 순서대로 한 열 | 높음 |
| 이미지 | 카드별 제품의 크기·배경·여백 통일. 기술 설명이 필요한 도면은 별도 설명 자료로 구분 | 기존 `next/image`, 비율·`object-fit` 조정 | 높음 |
| 타이포그래피 | 한글 제목의 굵기와 줄바꿈을 정리하고 크기 단계 유지 | 가독성 작업 유지. Pretendard는 별도 선택 | 높음 |
| 사업영역 | 같은 크기의 카드 반복을 줄이고 대표 이미지와 업무 목록에 위계 부여 | 우선 CSS. 짧은 등장 효과는 선택 | 중간 |
| 진행 과정 | 현재 단계 설명을 따라 읽기 쉬운 선·번호 구성 | CSS/SVG. 스크롤과 결합하더라도 강제 화면 고정은 피함 | 중간 |
| 문의 CTA | 배경 명암과 여백으로 명확히 구분. 문의 버튼을 쉽게 찾게 함 | CSS hover, 필요하면 Spotlight 한 곳 | 중간 |
| 헤더 | 로고·메뉴·문의 버튼 간격과 활성 메뉴 표시 정리 | 기존 Header 유지. 포커스·Escape 동작 보존 | 중간 |

글꼴 변경을 선택한다면 [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard)의 배포·라이선스와 실제 전송량을 확인한다. 한글 글꼴 파일은 최종 배치 확인 전에 적용해야 줄바꿈을 다시 맞추는 일을 줄일 수 있다. 기존 가독성 작업에는 없던 후속 선택이다.

### 추천하는 첫 시안의 범위

홈의 **첫 화면 + 대표 사례 + 문의 CTA**만 먼저 구성해 데스크톱과 모바일을 비교한다. 초기 시안은 기존 CSS로 만들고, 카드 hover 외 모션이 꼭 필요할 때만 Motion 또는 선택한 단일 컴포넌트를 추가한다. 첫 시안이 정해진 뒤 사업영역·회사소개·문의에 같은 규칙을 확장한다.

이 범위에서는 자동 재생 영상, 전체 화면 로딩 연출, 마우스 커서 교체, 강제 가로 스크롤, 긴 텍스트 타이핑 효과, 돌아가는 고객 로고 띠는 제외한다. 고객이 부품·실적·연락처를 찾는 데 도움이 되는 변화부터 적용한다.

## 7. 선택안과 필요한 준비

| 선택안 | 구성 | 직접 구매 비용 | 구현·유지 부담 | 추천 |
| --- | --- | --- | --- | --- |
| A. 기존 사이트 고도화 | 기존 CSS + 사진 정리 + 필요 시 Motion | 템플릿 구매 없음. 사진·제작 비용은 별도 | 낮음~중간 | **우선 선택** |
| B. 유료 코드 템플릿 활용 | Studio 등 구매 후 JNB 콘텐츠 이식 | 라이선스 금액 확인 필요 | 중간~높음. Tailwind·공통 구조 이식 | 전체 개편 시 비교 |
| C. 시각 편집 도구로 재구축 | Framer 템플릿 + 콘텐츠 재구성 | 템플릿·운영 요금 검토 | 높음. 현재 Next.js 운영 흐름 변경 | 비개발자 직접 운영이 목표일 때 |

실제 구현 전에 필요한 것은 다음 네 가지다.

1. **대표 이미지 선택:** 현재 공개한 제품 중 첫 화면·대표 사례에 쓸 사진과 원본 해상도. 사진이 부족하면 그래픽과 실물 사진의 역할을 구분한다.
2. **사업 우선순위 확인:** LCD·광학 센서·모터 등 어떤 품목과 소싱·양산·납품 업무를 먼저 보여줄지 확정한다.
3. **표현 방향 선택:** 밝은 산업형을 기본안으로 삼고, 필요하면 Studio형 사례 배치를 섞는다.
4. **유료 자산 필요 여부:** 초기 제안은 구매 없이 진행 가능하다. 실제 템플릿이나 사진 구매를 선택하면 대상과 조건을 확인한다.

이 문서는 후보 조사이므로 전체 플랫폼 변경을 확정하지 않는다. 큰 개편을 선택할 때는 운영 담당자·수정 방식·예산을 함께 비교한다.

## 8. 구현 시 검증 기준

- [가독성 계획](readability-plan.md)의 본문 크기·대비·320px 리플로우·텍스트 확대 기준을 유지한다.
- [모션 축소 설정](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)을 존중한다. Motion 도입 시 [접근성 안내](https://motion.dev/docs/react-accessibility)의 `useReducedMotion` 등도 검토한다. 기존 CSS의 모션 차단만으로 JavaScript 기반 효과까지 중지된다고 가정하지 않는다.
- JavaScript 로딩 실패·모션 비활성화·화면 밖 판정 오류가 있어도 제목·본문·링크가 영구히 투명하게 남지 않도록 한다.
- hover 효과는 터치·키보드 이용에서도 내용을 숨기지 않는다. 카드 이동·확대가 인접 글자와 포커스 표시를 가리지 않아야 한다.
- 이미지와 그래픽 영역의 크기를 미리 확보하고, 화면 밖 효과는 불필요하게 계속 실행하지 않는다. 정적인 배경으로도 같은 정보를 전달한다.
- 기존 5개 페이지 브라우저 검사, lint·빌드·테스트를 통과하고 효과 추가 전후의 로딩·상호작용을 같은 조건에서 비교한다.
- 성능 참고 목표는 [Core Web Vitals](https://web.dev/articles/vitals)의 LCP 2.5초 이하·INP 200ms 이하·CLS 0.1 이하(실사용 75번째 백분위)다. 로컬 Lighthouse 결과만으로 실사용 통과를 선언하지 않는다. 이번 조사에서는 이를 측정하지 않았다.
- 후보별 Next.js 16.4·React 19.3 호환성과 실제 의존성은 설치 전 확인하고 작은 시안에서 검증한다. 이번 조사는 호환성 테스트를 대신하지 않는다.

## 9. 조사 증거와 남은 확인

- 로컬 확인 캡처: `output/design-research/home-desktop.png`, `home-mobile.png`, `studio.png`. `output/`은 기존 Git 제외 경로이며 문서만 공유하면 캡처는 함께 전달되지 않는다.
- 운영 홈과 Studio 첫 화면은 시각 확인했다. Protolabs·Fictiv 및 나머지 라이브러리는 공식 페이지·문서·저장소를 확인했다. 모든 데모의 상호작용을 실행한 것은 아니다.
- Studio의 최신 가격·구매 조건, Industrial Factory 데모 동작, 도입 후보의 실제 번들 증가량·모바일 성능은 미확인이다.
- 템플릿 판매자의 접근성·반응형 지원 문구는 판매자 설명이며 JNB에 적용한 뒤의 품질을 보장하지 않는다.
- 홈페이지 코드와 다른 세션의 가독성 작업은 이번 조사에서 수정하지 않았다.
