# JNB 정식 배포 준비 체크리스트

작성일: 2026-10-13 · 기준 커밋: `7fae24a` · 상태: 준비 작업 미착수

목표는 홈페이지를 통해 부품 조달 문의를 받는 것이다. 이 문서는 여러 세션이 준비 작업을 나눠 수행하는 공통 작업판이다. 체크 완료는 실제 결과와 검증 근거가 있을 때만 표시한다.

## 새 세션 시작 방법

1. 이 문서, 저장소 지침, 현재 `git status`와 최근 커밋을 읽는다. 기준 커밋 이후 변경도 확인한다.
2. 아래 작업표에서 미배정 작업을 선택하고 담당 세션·시작 시각·상태를 기록한다. 같은 작업을 다른 세션이 진행 중이면 중복 작업하지 않는다.
3. 선행 조건과 파일 담당 범위를 확인한다. 공통 파일을 수정해야 하면 담당 세션과 순서를 정한다. 가능하면 별도 브랜치/작업 공간을 사용한다.
4. 작업별 완료 기준을 충족하고 검증한 뒤 Conventional Commits 형식으로 커밋한다. 사용자가 요청한 작업별 커밋·푸시 원칙을 따른다. 푸시 전 원격 변경을 확인하고 강제 푸시는 하지 않는다.
5. 체크박스·작업표·완료 기록을 함께 갱신한다. 확인하지 못한 외부 조건은 완료로 표시하지 않는다.

다른 세션에 전달할 요청 예시:

> `docs/production-release-checklist.md`를 읽고 R03을 맡아 진행해줘. 담당과 상태를 기록하고, 다른 작업의 파일을 건드리지 않도록 범위를 지켜줘. 완료 기준에 따라 검증한 뒤 작업별 커밋·푸시와 완료 기록까지 남겨줘.

이 문서의 생성만으로 공개 전환·DNS 변경·외부 메시지 발송을 실행하지 않는다. 해당 작업을 맡는 세션은 대화에서 받은 실제 실행 지시와 계정 권한을 확인한다. 이미 받은 권한을 반복해서 묻지 않는다. 테스트 메일도 사용자가 발송을 지시한 경우에만 보낸다.

- 6개 페이지: `/`, `/about`, `/services`, `/components`, `/portfolio`, `/contact`.
- 취급 부품 페이지 분리와 메뉴 연결 완료. 품목 검색·분류·메일 작성 링크 제공.
- 최근 빌드·린트·단위 테스트 4건·브라우저 18개 경로/화면 조합 통과. 중간 화면 너비의 헤더 배치도 확인.
- 런타임 의존성 `npm audit --omit=dev` 취약점 0건. 배포 직전 다시 확인한다.
- 기본 공개 설정은 비공개 검색 모드. 테스트 배너, robots meta, HTTP 헤더, robots.txt가 공개 설정에 연동된다.
- 이메일은 `comdj@naver.com`, 전화는 사용자 확인된 `010-4657-3241`. 실제 메일 수신·회신은 미확인.
- 정식 대표 URL 후보는 `https://www.jnbcompany.co.kr`. 현재 DNS·HTTPS·Vercel 연결 상태는 미확인.
- 기존 지식 그래프는 현재 소스와 달라 최신 파일을 기준으로 판단한다.
- 이번 작업과 관계없는 기존 변경·분석 파일은 임의로 커밋하거나 삭제하지 않는다.
- 사용자가 `Z:\5 GSPLPLUS JANDB\0.제이앤비컴퍼니` 하위 자료 사용을 허용했다. 개별 자료 사용 권한을 다시 묻지 않는다. 원본 문서 전체나 내부 정보를 웹에 그대로 올리지는 않는다.

## R01 — 공개 전환 설정

주 담당 파일: `src/lib/deployment.mjs`, `next.config.mjs`, `.env.example`, `tests/deployment.test.mjs`.

- [ ] `SITE_PUBLIC=true`가 정식 Production 빌드에만 적용되고 Preview는 계속 검색 제외되는지 확인한다.
- [ ] `SITE_URL`은 확정 대표 URL을 사용하고 정식 메타데이터에 localhost·테스트 호스트가 섞이지 않는지 확인한다.
- [ ] 테스트 배너·robots meta·`X-Robots-Tag`·robots.txt가 같은 공개 상태를 따르는지 확인한다.
- [ ] 배포 환경변수 변경 후 재빌드가 필요함을 운영 문서 담당에게 전달한다. 로컬 기본 설정을 무조건 공개로 바꾸지 않는다.
- [ ] 공개·검토용 설정 테스트를 실행하고 결과를 기록한다.

완료 기준: 설정과 전환 절차가 검증되어 있다. 실제 계정의 환경변수 변경·공개는 R08에서 수행한다.

## R02 — 연락처와 회사 정보

주 담당 파일: `src/data/site.ts`, `src/app/contact/page.tsx`, 필요 시 `src/components/Site.tsx`.

- [ ] 담당자가 이메일 수신·첨부·회신 가능 여부를 확인하고 확인일을 기록한다. 주소 변경 시 공통 데이터와 링크를 일치시킨다.
- [ ] 확인 후 “현재 사용 여부를 확인 중입니다” 문구를 제거하거나 실제 운영 안내로 바꾼다. 단순히 문구만 지우고 검증 완료로 처리하지 않는다.
- [ ] 전화·주소·3동 안내가 실제 운영 정보와 일치하는지 확인한다.
- [ ] 문의를 확인하고 회신할 담당을 정한다. 응답 시간은 운영자가 확정한 경우에만 게시한다.
- [ ] 대표자명·사업자등록번호 등 신뢰 정보 추가 여부를 확인한다. 전달받지 않은 정보를 임의로 쓰지 않는다. 미추가만으로 공개를 막지 않는다.

완료 기준: 실제 연락 가능한 주소와 담당이 확정되고 홈페이지 표기가 일치한다.

## R03 — 검색 노출 준비

주 담당 파일: `src/app/layout.tsx`, `src/app/robots.ts`, 신규 `src/app/sitemap.ts`, 각 페이지의 metadata.

- [ ] 정식 공개 시 6개 페이지에 각각 정확한 canonical을 제공한다. 모든 하위 페이지를 홈 URL로 지정하지 않는다.
- [ ] 정식 URL 기준 6개 페이지를 담은 사이트맵을 제공하고 robots.txt에서 연결한다.
- [ ] Preview의 검색 차단을 유지하고 사이트맵·공유 URL 정책도 함께 확인한다.
- [ ] 페이지별 제목·설명·Open Graph URL이 해당 페이지와 일치하도록 정리한다.
- [ ] 확인된 회사명·URL·연락처만으로 Organization 구조화 데이터 추가 여부를 검토한다. 넣지 않으면 이유를 기록하며 필수 공개 조건으로 취급하지 않는다.

완료 기준: 공개 모드의 생성 HTML과 사이트맵·robots 응답에서 URL·검색 설정을 실제 확인한다.

공통 파일 조율: R04가 만든 이미지 경로·크기 정보를 받아 R03 담당이 `layout.tsx`의 공유 메타데이터를 반영한다.

## R05 — 검수 자동화

주 담당 파일: `tests/browser-check.mjs`, 필요 시 `tests/deployment.test.mjs`는 R01 담당과 조율.

- [ ] 검토용·정식 공개 모드를 명시적으로 선택해 검사하도록 한다. 현재 `noindex`·`Disallow: /` 고정 검사는 정식 사이트에서 사용할 수 없다.
- [ ] 공개 모드에서 배너 없음, index 허용, noindex 헤더 없음, robots 허용을 확인한다.
- [ ] 검토용 모드에서 기존 검색 차단과 배너가 유지되는지 확인한다.
- [ ] 페이지별 canonical, 사이트맵, 공유 이미지·아이콘을 검사한다.
- [ ] 6개 경로의 직접 접속·새로고침·404·모바일 메뉴·가로 넘침·이미지·검색·분류·문의 링크 검사를 유지한다.
- [ ] 360·768·1440px 및 헤더가 전환되는 중간 너비를 확인한다.

완료 기준: 각 모드에 맞는 빌드를 대상으로 검사하고 URL·커밋·결과를 기록한다. 검토용 빌드 통과를 정식 배포 통과로 대신하지 않는다.

후속 작업. 측정 도구·계정·데이터 범위를 정한 후 담당 파일을 배정한다.

- [ ] 방문 페이지, 부품 검색, 분류 선택, 이메일·전화 클릭 중 필요한 지표를 정한다.
- [ ] 품번·검색어·이메일·전화번호 등 입력값을 무분별하게 외부 분석 도구로 보내지 않는다. 기본은 클릭 종류와 품목 분류 정도로 제한한다.
- [ ] 클릭 수와 실제 문의 접수 건수를 구분해 해석한다.
- [ ] 운영 담당이 결과를 확인하고 품목 보강·문구 개선에 활용할 수 있도록 한다.

완료 기준: 선택한 이벤트를 검증하고 계정·확인 방법을 문서화한다. 도구가 미선정이면 이 항목은 미완료로 남긴다.

## 세션별 완료 기록

각 세션은 아래 양식을 복사해 기록한다. 체크리스트 파일 동시 수정 시 다른 세션의 기록을 보존한다.

```md
### Rxx — 작업명
- 담당 세션 / 시작·완료 시각:
- 상태:
- 변경 내용과 파일:
- 검증 명령 / 대상 URL / 공개 모드:
- 검증 결과와 근거 파일:
- 커밋 / 브랜치 / 푸시 결과:
- 외부 확인 대기 / 남은 제한:
- 다음 담당에게 전달할 사항:
```
