# JNB 회사 홈페이지 요구사항서

- 작성일: 2026-10-08
- 버전: 0.2
- 상태: 최초 테스트 배포용 요구사항
- 기준: [홈페이지 전략](website-strategy.md), [타당성 검토](website-strategy-review.md), 테스트용으로 먼저 배포하고 이후 수정한다는 사용자 결정

JNB의 회사 소개, 사업영역, 경험과 문의 방법을 웹에서 확인할 수 있는 초안을 만든다. 첫 목표는 대표님과 실제 화면을 보며 수정할 수 있는 테스트 URL을 제공하는 것이다. 사업별 비중, 최종 문구, 사례 수, 구매한 도메인의 연결과 운영 담당자 확정은 테스트 결과를 보며 진행한다. 이 항목들의 미확정만으로 초안 제작을 멈추지 않는다.

## 1. 범위와 제작 기준

| 구분 | 내용 |
| --- | --- |
| 최초 테스트 배포 필수 | 한국어 회사 홈페이지, 아래 5개 페이지, 공통 메뉴·푸터, 모바일 대응, 수정 가능한 콘텐츠 데이터, 검토용 콘텐츠 구분, 테스트 검색 제외 |
| 자료가 있을 때 적용 | 실제 로고·제품 사진·사례·대표자 경력, 이메일·전화·주소·지도 링크 |
| 테스트 후 수정 | 첫 화면 문구, 주력 사업 강조 순서, 사례 추가·교체, 페이지 통합 여부, 색상·이미지·여백 |
| 정식 공개 준비 | 확정된 회사 정보·연락처·실적·이미지, 도메인, 계정·비용·수정·문의 담당, 검색 등록 |
| 후속 선택 | 사례 상세 페이지, 첫 화면 영상, 영문 사이트 |
| 초기 제외 | 회원·로그인·결제·쇼핑·관리자·CMS·문의폼·문의 저장·자동 메일 발송·데이터베이스·API 서버 |

초기 소개 방향은 ‘디자인부터 양산까지 연결하는 파트너’로 유지한다. 디자인·개발, 부품 소싱·공급, OEM·ODM 양산의 세 묶음을 사용한다. 이 방향을 새로 검토하는 절차를 선행시키지 않고, 실제 화면을 검토하며 강조점과 표현을 조정한다.

## 2. 페이지와 콘텐츠 요구사항

| ID | 경로·메뉴 | 필수 내용 | 자료가 부족할 때 | 검수 기준 |
| --- | --- | --- | --- | --- |
| P-01 | `/` · 홈 | 핵심 소개, 대표 사례 영역, 세 사업영역 요약, 진행 방식·강점, 문의 안내 | 사례는 검토용 카드로 표시하거나 생략하고 업무·진행 방식을 먼저 보여준다 | 처음 방문한 사람이 회사의 업무와 문의 위치를 찾을 수 있고 모든 이동 버튼이 연결됨 |

| P-03 | `/services` · 사업영역 | 세 사업 묶음별 설명, 지원 항목, 진행 과정, 문의 연결 | 소개서·기존 홈페이지를 바탕으로 검토용 문구를 쓰고 미확정 범위는 표시 | 어떤 일을 상담할 수 있는지 설명하며 자체 수행·협력사 연계를 확인된 범위에서 구분함 |
| P-04 | `/portfolio` · 포트폴리오 | 사례 목록, 제품·분야, 과제, 수행 주체·역할·범위, 결과, 이미지 | 실제 사례가 없으면 ‘사례 자료 정리 중’ 안내와 검토용 카드로 레이아웃을 확인 | 가상 고객·성과를 실제 실적으로 제시하지 않으며, 사례 3~6건 확보가 배포 필수 조건이 아님 |
| P-05 | `/contact` · 문의·오시는 길 | 이메일 안내, 첫 문의에 도움이 되는 항목, 확보한 전화·주소, 지도 길찾기 | 미확정 연락처는 ‘연락처 확인 중’으로 표시하고 해당 동작을 제공하지 않는다 | 실제 값이 있는 연락 수단만 동작하고 존재하지 않는 주소·전화·지도 링크를 만들지 않음 |

홈의 기본 순서는 **핵심 소개 → 대표 사례 → 사업영역 → 진행 방식·강점 → 문의**다. 사례가 없을 때는 대표 사례 구간을 생략해 나머지 흐름을 유지할 수 있다. 초기 포트폴리오는 목록형으로 만들며 별도 상세 페이지·필터·검색·페이지 나누기는 넣지 않는다.

첫 화면 문구의 시작안:

> 제품의 아이디어부터 양산과 공급까지
>
> 디자인과 부품 소싱부터 OEM·ODM 생산, 품질·납품 대응까지 함께합니다.

문구는 데이터로 관리해 대표님 검토 후 바꿀 수 있어야 한다. ‘포트폴리오 보기’와 ‘문의하기’를 주요 이동 버튼으로 두되, 사례가 없는 상태에서는 첫 버튼을 ‘사업영역 보기’로 바꾼다.

## 4. 콘텐츠와 자료 관리

화면 구조와 콘텐츠를 분리해 회사 소개·사업영역·사례·연락처를 저장소의 데이터 파일에서 수정한다. 별도 관리 화면이나 복잡한 콘텐츠 관리 시스템은 만들지 않는다.

| 데이터 | 관리할 내용 |
| --- | --- |
| 회사·연락처 | 표시명, 소개 문구, 확보한 영문명·로고·이메일·전화·주소·지도 URL |
| 사업영역 | 식별자, 제목, 요약, 지원 항목, 진행 방식, 수행 범위 설명, 표시 순서 |
| 사례 | 식별자, 제목, 제품·분야, 과제, 수행 주체, 역할·범위, 결과, 이미지·대체 설명, 표시 순서, 검토용 여부 |
| 화면 문구 | 홈 제목·설명, 강점·진행 과정, 문의 안내, 자료가 없을 때의 안내 |
| 배포 설정 | 테스트/정식 구분, 현재 배포 URL, 정식 사이트 URL 후보 `https://www.jnbcompany.co.kr/`, 검색 노출 여부 |

회사의 같은 소개·사업명·연락처가 여러 페이지에 나와도 기준 데이터를 공유한다. 특정 사례나 연락처를 숨길 수 있고, 숨긴 항목 때문에 빈 카드·깨진 이미지·동작하지 않는 버튼이 남지 않아야 한다.

자료는 `Z:\5 GSPLPLUS JANDB\0.제이앤비컴퍼니`의 기존 홈페이지 자료·소개서·제품 사진을 먼저 활용한다. 이후 필요한 내용만 관련 회사 폴더에서 보완한다. 모든 하위 자료의 조사 완료를 테스트 배포 조건으로 삼지 않는다.

웹에 넣을 후보의 출처·날짜·수행 주체·활용 위치·공개 여부는 제작용 자료 목록에 기록한다. 이 목록과 원본 문서·내부 자료는 웹 자산에 포함하지 않는다. 제품 사진이나 회사명을 익명화한 사례도 원래 자료의 사용 가능 범위를 확인한다. 확인 전에는 텍스트 안내·검토용 그래픽으로 대체할 수 있다.

고객사 로고·공식 협력사 관계, 삼성전자·LG 관련 경력, ‘리스크 0%’·‘원가 50% 절감’ 등은 확인된 표현만 사용한다. 대표자 과거 경험을 JNB 회사 실적으로 바꾸지 않는다. 검토용 카드는 실제 고객명·수치·성과를 꾸며 채우지 않는다.

### 구매 도메인과 연결 계획

| 항목 | 요구사항 |
| --- | --- |
| 구매 정보 | 사용자 제공 기준 구매 완료. 전달받은 주소는 `http://www.jnbcompany.co.kr/`, 구매 도메인은 `jnbcompany.co.kr`, 사용할 호스트는 `www.jnbcompany.co.kr` |
| 이번 테스트 배포 | Vercel 기본 URL에서 테스트한다. 구매 도메인은 후속 연결 대상으로 기록하고 이번 배포에서 DNS 변경이나 도메인 연결을 선행하지 않는다 |
| 정식 URL 기준 | 추후 연결 시 `https://www.jnbcompany.co.kr/`을 대표 URL의 기본안으로 사용한다. HTTPS·인증서 적용 상태는 실제 연결 시 확인한다 |
| 설정 관리 | 배포 URL과 정식 사이트 URL을 구분해 한 곳에서 관리한다. 페이지·메타데이터에 테스트 호스트를 반복해서 하드코딩하지 않는다 |
| 추후 연결 | 현재 Vercel 프로젝트에 구매 도메인을 연결하고 DNS·HTTPS를 확인한다. `www` 없는 주소 `jnbcompany.co.kr`도 대표 주소로 연결되도록 설정·검수한다 |

테스트는 Vercel 기본 URL을 사용하고 구매 도메인 연결을 기다리지 않는다. 실제 계정의 사용 가능한 플랜·배포 권한·비용은 배포 시 확인한다. 테스트라는 이름만으로 상업 사이트의 플랜 조건이 달라진다고 가정하지 않는다.

테스트 배포에는 검토 가능한 공개 자료와 자리표시자를 사용한다. 내부 자료를 포함해야 하는 별도 검토본은 접근 제한을 적용한다. 검색 제외 설정을 접근 제한으로 대신하지 않는다.

각 페이지의 제목·설명과 기본 공유 정보를 준비한다. 정식 공개 준비 때 구매 도메인의 연결 상태와 대표 URL을 확인하고 canonical·공유 URL·사이트맵·구조화 데이터를 같은 정식 URL 기준으로 맞춘다. 연결 전에는 테스트 URL을 정식 대표 URL로 고정하거나 미연결 도메인으로 방문자를 자동 이동시키지 않는다. 검색엔진 등록은 정식 공개 단계에서 진행한다.

## 6. 제작 순서와 테스트 완료 기준

1. 기존 홈페이지 자료에서 사용할 로고·문구·사진·사례 후보를 선별하고 나머지는 검토용 안내로 대체한다.
2. 공통 레이아웃, 홈의 첫 화면·사업영역·사례 영역을 먼저 만든다.
3. 회사소개·사업영역·포트폴리오·문의 페이지와 모바일 동작을 연결한다.
4. 아래 필수 검수를 마친 뒤 테스트 URL을 제공한다.
5. 대표님과 문구·사진·사례·사업 비중을 수정하며 반복 배포한다.
