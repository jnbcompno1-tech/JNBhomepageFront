## 1. 목표와 방문자

홈페이지는 다음 두 경로로 들어오는 기업 담당자가 JNB의 업무와 경험을 확인하고 이메일로 문의하는 것을 목표로 한다.

| 방문 경로 | 방문자가 확인하려는 것 | 제공할 정보 |
| --- | --- | --- |
| 명함을 받고 회사명을 검색 | 어떤 회사인지, 믿고 연락할 수 있는지 | 회사 소개, 실제 경험, 포트폴리오, 연락처 |
| 디자인·개발·양산 파트너를 검색 | 필요한 업무와 유사 사례를 지원하는지 | 구체적인 사업영역, 수행 역할, 진행 과정, 이메일 문의 |

초기에는 회원가입·결제·관리자·문의 저장용 백엔드 없이 운영한다. 문의는 공개 이메일 주소와 메일 작성 링크로 연결한다. 메일 프로그램이 없는 환경에서도 주소를 직접 확인할 수 있어야 한다.

## 2. 회사의 소개 방향

잠정 소개 방향은 **‘디자인부터 양산까지 연결하는 파트너’**다. 여러 역량을 생산과 공급이라는 결과에 연결해 설명한다. 이 방향과 사업별 비중은 대표님 검토에 따라 수정할 수 있다.

첫 화면 문구 초안:

> 제품의 아이디어부터 양산과 공급까지
>
> 디자인과 부품 소싱부터 OEM·ODM 생산, 품질·납품 대응까지 함께합니다.

| 사업 묶음 | 포함할 수 있는 내용 | 확인할 사항 |
| --- | --- | --- |
| 디자인·개발 | 제품디자인, 기구·회로설계, 목업·시제품 | 직접 수행과 협력사 연계 범위 |
| 부품 소싱·공급 | 디스플레이, 센서, 반도체 및 기타 전자부품 | 현재 취급 품목, 공급 가능 범위 |
| OEM·ODM 양산 | 중국 업체 직접 소통, 생산 원가 조율, 품질·배송·문제 대응 | 실제 책임 범위와 사례 |

사업을 모두 같은 비중으로 나열하지 않는다. 실제 사례와 확보된 근거에 따라 강조 순서를 정한다. 초기 홍보 문구가 계약상 보증이나 모든 업무의 자체 수행으로 읽히지 않도록 표현한다.

조사 절차:

1. 폴더·파일 목록을 작성한다. `node_modules`, `.git`, `.next`, 중복 코드 백업 등은 콘텐츠 조사에서 제외한다.
2. 소개서·제품자료·프로젝트 문서·사진을 우선 확인하고, 압축파일은 필요한 경우에만 내용을 확인한다.
3. 각 후보에 원본 경로, 문서 날짜, 설명, 수행 주체, 활용할 페이지, 공개 여부, 확인할 질문을 기록한다.
4. 동일 정보가 다르면 최신성만으로 확정하지 않고 대표님 확인 항목으로 남긴다.
5. 후보를 ‘공개 가능 / 확인 필요 / 비공개’로 구분한다. 공개가 확인된 자료만 웹 자산으로 옮긴다.
6. 중복 이미지를 정리하고 웹용 크기·형식으로 변환한다. 원본 문서와 내부 정보가 담긴 파일을 통째로 배포하지 않는다.

자료를 최대한 활용한다는 뜻은 많이 게시한다는 뜻이 아니다. 넓게 확인한 근거로 정확한 소개와 설득력 있는 사례를 고른다.

## 5. 초안의 페이지 구성

| 페이지 | 역할 | 주요 내용 |
| --- | --- | --- |
| 홈 | 회사 이해와 사례 탐색 유도 | 핵심 소개, 대표 포트폴리오, 사업영역, 강점, 이메일 문의 |
| 회사소개 | 회사 확인과 신뢰 형성 | 회사 정보, 대표자 경험, 업무 방식 |
| 사업영역 | 지원 가능한 업무 설명 | 디자인·개발, 부품 소싱·공급, OEM·ODM 양산 |
| 포트폴리오 | 실제 수행 역량 확인 | 제품 사진, 해결 과제, 담당 역할, 결과 |
| 문의·오시는 길 | 상담 연결 | 이메일, 확인된 전화번호·주소, 지도 길찾기 링크 |

홈 흐름은 ‘핵심 소개 → 대표 포트폴리오 → 사업영역 → 진행 방식·강점 → 이메일 문의’로 제안한다. 메뉴와 페이지 수는 요구사항 단계에서 확정한다.

포트폴리오 후보는 우선 3~6건을 목표로 조사한다. 실제로 공개 가능한 사례가 적으면 수를 줄이고, 가상의 사례로 채우지 않는다. 공개 전 검토용 자리표시자는 실제 실적으로 보이지 않도록 표시한다.

각 사례는 제품·분야, 고객의 과제, JNB 또는 대표자의 역할, 수행 범위, 공개 가능한 결과, 이미지와 출처를 담는다. 고객명이 비공개여도 역할을 설명할 수 있는지 확인한다. 상세 페이지는 정보량이 충분한 경우에만 추가한다.

## 6. 디자인 방향

GSPLPLUS의 기업 소개 → 서비스 → 실제 사례 → 문의 흐름과 공통 레이아웃 방식을 참고한다. JNB의 로고·사진·사업 내용에 맞춰 다시 구성한다.

- 흰색 배경과 읽기 쉬운 글자, JNB 로고의 파랑을 중심으로 한 색상안을 먼저 제시한다.
- 실제 제품·작업 사진을 우선 사용한다. 첫 화면 영상은 자료 적합성·권리·모바일 성능을 확인한 후 결정한다.
- 이미지 안의 설명은 가능하면 HTML 텍스트로 옮긴다.
- 모바일, 키보드 이동, 글자 대비, 이미지 대체 설명, 움직임 감소 설정을 고려한다.
- 대표님 검토가 쉽도록 첫 화면과 대표 포트폴리오부터 시안을 만든다.

## 7. 기술·운영 방향

잠정 기술 구성은 Next.js App Router, TypeScript, CSS Modules이며 Vercel 배포를 전제로 한다. GSPLPLUS의 공통 컴포넌트·데이터 관리·SEO 방식에서 필요한 부분을 재사용한다.

- 소개·서비스·사례는 저장소의 데이터 파일과 웹 자산으로 관리한다. 변경은 수정 후 재배포한다.
- 본문은 빌드 시 정적 생성하고, 모바일 메뉴 등 필요한 상호작용만 클라이언트에서 처리한다.
- API, 데이터베이스, 로그인, 문의 저장·자동 메일 발송은 초기 범위에 포함하지 않는다.
- 이메일 링크는 사용자의 메일 작성 화면을 연다. 사이트 자체에서 전송 성공을 표시하지 않는다.
- Vercel 배포 시 정적 생성과 `output: 'export'`는 별개 선택이다. 순수 정적 파일만 배포할지, Vercel의 이미지 최적화 등을 사용할지는 타당성 검토에서 확인한다.
- 패키지 버전은 구현 시점에 지원·보안 상태를 확인한다. 참고 프로젝트의 버전을 그대로 고정하지 않는다.
- GSPLPLUS의 회사명·도메인·연락처·로고·검색 소유확인 파일·실적은 JNB에 복사하지 않는다.

Vercel Hobby는 개인·비상업 용도로 제한되어 있으므로 회사 홈페이지는 Pro 비용을 전제로 검토한다. 실제 계정·플랜·도메인은 배포 전에 확인한다.

2026-10-08 도메인 정보 추가: 사용자 제공 기준 `jnbcompany.co.kr` 구매 완료. 전달받은 주소는 `http://www.jnbcompany.co.kr/`이다. 이번에는 Vercel 기본 URL에 테스트 배포하고 도메인은 나중에 연결한다. 정식 대표 URL의 기본안은 `https://www.jnbcompany.co.kr/`이며 실제 연결 시 DNS·HTTPS와 `www` 없는 주소의 연결을 확인한다. 배포·메타데이터 설정은 이 도메인으로 전환할 수 있게 관리한다. 세부 기준은 [요구사항서](website-requirements.md)의 구매 도메인과 연결 계획을 따른다.

## 8. 검색 유입 준비

회사명 검색과 업무 검색을 함께 고려한다. 회사명은 제이앤비컴퍼니·JNB·J&B COMPANY 표기의 관계를 확인하고 일관되게 사용한다.

업무 검색어 후보는 제품디자인, 시제품 제작, 중국 OEM·ODM, 제품 양산, 디스플레이·센서 소싱이다. 실제 지원 업무와 주력 고객을 확인한 뒤 페이지별 표현을 정한다.

페이지별 제목·설명, 대표 URL, 공유 이미지, 사이트맵, robots, 구조화 데이터를 준비한다. 구매 도메인의 연결과 정식 대표 URL 확정 후 검색엔진 소유확인을 진행한다. 검색 순위나 노출 시점을 보장하지 않는다. 미확인 콘텐츠가 있는 검토용 배포는 검색에 노출되지 않도록 관리한다.
