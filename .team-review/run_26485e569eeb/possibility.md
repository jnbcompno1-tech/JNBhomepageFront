# 가능성 검토 보고서

- 검토일: 2026-10-08
- 대상: `docs/website-strategy.md` 1~170줄
- 역할: 가능성 검토자 — 기대 효과·성립 조건·최소 검증·조사 우선순위
- 범위: 대표님과 검토할 B2B 홈페이지 초안을 준비하는 전략의 타당성. 구현·배포 승인을 판단하지 않는다.
- 참여: 배정된 검토자 1명이 독립 검토했다. 다른 검토자 보고서 열람, 팀 검토 재실행, 하위 작업자 생성은 하지 않았다.
- 확인 수준: 전략 원문만 읽었다. 원문이 소개하는 회사 자료·실적·권리·연락처·운영 조건은 독립 확인하지 않았다. GSPLPLUS 코드와 그래프를 JNB 실적의 근거로 사용하지 않았다.

## 판단: 조건부 통과

회사 업무·경험을 확인하고 이메일로 문의한다는 목표에 맞춰, 대표님과 논의할 초안의 기준으로 사용할 수 있다. 목표와 초기 제외 범위가 명확하고, 미확인 실적을 확정하지 않으며 사례 수를 줄일 수 있는 장치가 있다. 아래 조건은 자료 확인과 요구사항 확정 시점에 해결하고, 구현 승인은 원문 136줄의 별도 절차를 따른다.

## 핵심 의견 1. 소개 방향과 사례 중심 구성을 한 건의 근거로 먼저 확인하면 효과가 크다

- **근거 / 원문 줄번호:** 10~17줄은 방문자의 업무 확인과 문의를 목표로 한다. 21~35줄은 디자인부터 양산까지를 잠정 방향으로 두지만, 49줄에는 자료별 강조점 차이가 있고 53~55줄은 대표자 경험과 회사 실적의 구분이 미확인임을 밝힌다. 93~95줄은 사례 수 축소와 역할·결과·출처 기록을 허용한다.
- **추정:** 현재 주력 업무에 맞는 사례 하나만 구체적으로 설명해도 대표님은 소개 문구와 홈페이지 흐름을 평가할 수 있을 것이다. 실제 사례 확보 가능성과 방문자 설득 효과는 아직 확인하지 않았다.
- **영향:** 근거 있는 대표 사례와 주력 업무가 연결되면 넓은 역량 나열보다 상담 가능한 범위를 설명하기 쉽다. 반대로 과거 경력이나 협력사 역할을 회사의 직접 수행으로 읽히게 하면 첫 화면 전체를 다시 작성해야 한다.
- **가장 작은 확인 방법 / 팀장 요청:** 대표님께 현재 가장 받고 싶은 문의 유형 하나와 이를 설명할 후보 사례 하나를 요청한다. 후보에는 수행 주체, 직접 수행·협력사 범위, 시기, 결과의 근거, 공개 가능한 문구·이미지 여부만 우선 기록한다. 검토용 첫 화면 문구 하나와 사례 설명 한 건을 함께 읽고 실제 업무와 맞는지 확인한다. 후보 한 건은 초기 판단용이며 최종 포트폴리오 건수를 미리 확정하는 조건이 아니다.
- **보완 시점:** 요구사항서에서 첫 화면 문구와 포트폴리오 구성을 확정하기 전. 공개 권한은 웹 자산으로 옮기기 전 확인한다.
- **판단을 바꿀 조건:** 현재 업무가 소싱·공급에 집중되어 있으면 소개의 중심과 강조 순서를 바꾼다. 공개 사례가 없으면 확인된 업무 범위·진행 과정으로 검토용 구성을 바꾸고, 포트폴리오 중심 전략은 보완 후 재검토한다. 이는 전체 홈페이지 가능성을 부정하는 조건은 아니다.

## 핵심 의견 2. 이메일 문의만으로 시작하는 범위는 목표에 맞으며, 실제 연락 경로의 성립을 확인하면 된다

- **근거 / 원문 줄번호:** 17줄은 이메일 주소와 메일 작성 링크를 함께 제공한다. 89~91줄은 문의 위치와 홈 흐름을 제안한다. 113~114줄은 문의 저장·자동 발송을 제외하고 사이트가 전송 성공을 표시하지 않도록 한다. 152줄과 164줄은 이메일 방식의 적합성과 실제 연락처를 후속 확인으로 남긴다.
- **추정:** 초기 방문자가 회사 정보를 확인한 뒤 직접 이메일을 보내는 방식으로 상담을 시작할 수 있을 것이다. 문의 빈도, 고객의 메일 사용 환경, 담당자의 회신 가능 여부는 확인하지 않았다.
- **영향:** 별도 문의 시스템 없이도 목적을 달성할 가능성이 있고 초기 준비 범위를 작게 유지할 수 있다. 다만 메일 앱이 없는 방문자에게 주소가 보이지 않거나 수신·회신 주체가 없으면 핵심 목표가 성립하지 않는다.
- **가장 작은 확인 방법 / 팀장 요청:** 대표님께 공개 가능한 실제 수신 주소와 회신 담당자, 초기 문의를 이메일로 받을 수 있는지 확인한다. 검토용 문안에 주소를 직접 표시하고, 대표님 또는 잠재 고객 역할의 검토자에게 문의할 위치와 연락 방법을 찾게 한다. 수신 계정 확인과 메일 링크·주소 표시의 실제 동작 검증은 승인된 구현·검수 단계에 팀장이 배정한다. 이번 검토에서는 메일을 보내지 않았다.
- **보완 시점:** 요구사항 확정 전에 주소·담당자·방식 적합성을 확인하고, 실제 수신과 메일 앱이 없는 환경의 연락 가능 여부는 공개 전 검수한다.
- **판단을 바꿀 조건:** 고객이 사이트 내 접수·첨부·처리 상태 확인을 필수로 요구하거나 회사가 이메일 회신을 운영할 수 없으면 문의 범위를 다시 검토한다. 그 필요가 확인되기 전에는 문의 폼이나 백엔드를 추가할 이유가 없다.

## 핵심 의견 3. 넓은 조사는 계획으로 유지하되, 초안 판단에 필요한 자료부터 확인하는 순서가 필요하다

- **근거 / 원문 줄번호:** 59~79줄은 여러 회사 폴더의 조사와 후보별 근거 기록을 계획한다. 105줄은 첫 화면과 대표 포트폴리오부터 검토하도록 한다. 109~119줄은 잠정 기술·재배포 운영·비용 전제를 기록한다. 136~153줄은 단계별 판단과 운영 조건 확인을 요구한다.
- **추정:** 현재 주력 업무, 사례 후보, 연락처를 먼저 확인하면 대표님이 초안 방향을 판단하는 데 필요한 불확실성이 가장 빨리 줄어들 것이다. 전체 자료량과 조사 소요 시간, 운영 인력·예산은 확인하지 않았다.
- **영향:** 모든 폴더 조사를 끝내야 초안을 검토할 수 있다고 해석하면 의사결정이 늦어진다. 반대로 최소 자료만으로 최종 공개까지 승인했다고 해석하면 근거·권리·운영 확인이 누락된다.
- **가장 작은 확인 방법 / 팀장 요청:** 조사 순서를 ① 현재 주력 업무·받고 싶은 문의·실제 이메일 확인 ② 기존 홈페이지 자료에서 사례 후보 한 건과 출처 확인 ③ 빈칸이 남는 항목에 한해 다른 폴더 조사로 정한다. 대표님이 첫 화면 문구·후보 사례·문의 방법을 평가할 수 있으면 최초 초안 검토를 진행한다. 기술 선택을 확정하기 전에는 콘텐츠 수정·재배포 담당자와 운영비 승인 주체를 확인하고, 배포 전에는 실제 계정·플랜·도메인 조건을 팀장이 별도 검증한다. 특정 서비스의 현재 요금·이용 조건은 이번 검토에서 검증하지 않았다.
- **보완 시점:** 후속 조사 착수 전에 우선순위를 정한다. 운영 담당과 예산 전제는 요구사항 확정 전, 실제 배포 조건은 공개 전 확인한다.
- **판단을 바꿀 조건:** 우선 조사에서도 현재 업무와 사례를 설명할 근거가 없으면 콘텐츠 전략을 보완 후 재검토한다. 수정·재배포를 맡을 주체가 없거나 비용 전제가 수용되지 않으면 운영·배포 방향을 재검토하되, 회사 소개와 이메일이라는 목표는 유지할 수 있다.

## 제한과 남은 확인

이 보고서는 조사·확인 요청을 제안한 문서 검토 결과이며, 회사 역량이나 웹사이트 성과를 검증한 결과가 아니다. 원본 자료 열람, 외부 사실 확인, 코드 실행·설치·테스트, 메일 발송, 전략 수정·배포·커밋은 하지 않았다.
